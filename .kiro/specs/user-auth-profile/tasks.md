## Overview

خطة تنفيذية مرقّمة لإضافة المصادقة (بريد + Apple)، الملف الشخصي، وحذف الحساب.
كل مهمة مربوطة بمتطلباتها. تُنفَّذ المجموعات بالترتيب لأن كل مجموعة تعتمد على سابقتها.

## Task Dependency Graph

تُنفَّذ المهام على موجات (waves)؛ كل موجة تعتمد على اكتمال ما قبلها. المهام داخل
الموجة الواحدة يمكن تنفيذها بالتوازي.

```json
{
  "waves": [
    { "wave": 1, "tasks": ["1.1", "1.2", "1.3", "1.4", "1.5"], "dependsOn": [] },
    { "wave": 2, "tasks": ["2.1", "2.2", "2.3"], "dependsOn": ["1.1", "1.3"] },
    { "wave": 3, "tasks": ["3.1", "3.2"], "dependsOn": ["2.1"] },
    { "wave": 4, "tasks": ["4.1", "4.2", "4.3", "4.4", "4.5", "5.1", "5.2", "7.1", "7.2"], "dependsOn": ["3.1", "3.2"] },
    { "wave": 5, "tasks": ["6.1", "6.2", "6.3"], "dependsOn": ["1.4", "3.1"] },
    { "wave": 6, "tasks": ["8.1", "8.2"], "dependsOn": ["4.1", "4.4", "5.2", "6.3", "7.1"] }
  ]
}
```

- الموجة 1 أساس لكل ما بعدها (المخطط + RLS).
- الموجة 4 (الشاشات + الملف + المزامنة) تعتمد على سياق المصادقة (3).
- الموجة 5 (الحذف) تعتمد على المخطط (1) والسياق (3).
- الموجة 6 أخيرة (تحقق شامل + إعداد خارجي).

## Notes

- الحزم الجديدة: `@supabase/supabase-js`, `expo-apple-authentication`.
- تدفّق Apple يتطلب جهازاً حقيقياً (لا يعمل في Expo Go/المحاكي).
- `SUPABASE_SERVICE_ROLE_KEY` يُضبط في api-server (Coolify) فقط — لا في التطبيق.
- تحديث `.env.example` بالمتغيّرات الجديدة دون قيم سرّية.
